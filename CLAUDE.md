## The "classic" look (default, Settings → admin_theme)
Copies the appraisers' valuation portal, light blue (`admin_color`: azure / orange).
- CSS: `public/css/admin-classic.css` (tokens `--accent*` on `body.theme-classic`). JS: `public/js/admin.js`.
- Real estate: `resources/views/admin/real-estates/portal.blade.php` is the add, edit and object page (one form `#object-form` → `RealEstateController::store/main`), with `_portal-steps`, `_portal-top` (two columns), `_main-fields`, `_portal-approach`, `_portal-status` (Holat/Tarixi), `_map-picker` (`compact`).
- Lists: `admin/objects/index.blade.php` (`$classic` branch); real estate rows `real-estates/_portal-row.blade.php`.
- Clients: `admin/clients/index.blade.php` (classic branch), `admin/clients/portal-form.blade.php`; "Qo'shish yangi (pasport)" reads a passport photo (`ClientController::passport`, `DocumentAi`).
- Mixed property, vehicles, damage: `usesPortal()` in their controllers → one page `admin/objects/portal.blade.php` (add, edit and object page) with `admin/{slug}/_portal-top` (two columns), `_portal-middle`/`_portal-more` (folds), `objects/_portal-docs` (boxes saved with the form as `documents[kind][]`), `objects/_portal-holat` (assets only). Lists: `admin/{slug}/_portal-head` + `_portal-row`; filters from `portalFilters()`. No notes or hints on these pages.
- No licence and no plans (the user removed both): the system always works. A user may have `access_until`; after it `EnsureAccessAllowsChanges` (alias `access`, `App\Support\Access`) makes the panel read-only for them; main admins have no end. AI needs only `ANTHROPIC_API_KEY` (`ClaudeDocumentAi`/`ClaudeListingAi::available()`; texpasport → `VehicleController::techPassport`).
- Codespaces: `.devcontainer/setup.sh` (install), `serve.sh` (server; starts one `update.sh --watch`, pid in `.devcontainer/.updater.pid`), `update.sh` (fast-forward pull every 5 min, then `setup.sh` if `composer.lock`/`setup.sh` changed, else migrate).
- Cloudflare (Workers & Pages project `fair-value`, built from this branch with `npx wrangler deploy`): `wrangler.jsonc` serves only `cloudflare/index.html`, a standalone HTML demo of the dashboard (sample data in the browser, made in claude.ai; not built from Laravel). PHP cannot run on Cloudflare.
- Always-on server: `server/install.sh` (`curl … | sudo bash` on a fresh Ubuntu, e.g. Oracle Cloud Always Free): PHP 8.3-FPM, Caddy (own https), `/var/www/fair-value`, `deploy.sh`, cron (schedule + `queue:work --stop-when-empty`); without `DOMAIN` the address is `<ip-with-dashes>.sslip.io`; running it again updates. Oracle images also need ports 80/443 in the VCN security list (the script opens the instance's iptables).
- `php artisan share` (`App\Console\Commands\ShareLink`, Windows `LINK-OCHISH.bat`): a Cloudflare quick tunnel to the local `artisan serve`; refused while any active user still has `ADMIN_PASSWORD`; cloudflared downloaded once into the base path. Trusted proxies default to loopback (`config/trustedproxy.php`).
- Organisations (`Organization`, `App\Support\Tenant`, middleware `workspace` before route bindings): clients and valuation objects use `BelongsToOrganization` (global scope by `organization_id`, null = the main company); activities carry `organization_id` (filtered in `ActivityController`). `Setting::get` reads an organisation's own details (`Organization::OWN_SETTINGS`), `Setting::main` the main company's. Gates `admin`/`manage-catalogs`/`main-workspace` = main company only. `ValuationHistory` (`admin.history`, `data-history` on inputs) shows who and when only.
- Real estate "Akt" (from the portal's screenshot): a window (`<dialog>`, `data-act-open` links on the list rows and the object page) loading `real-estates/_act` from `RealEstateController::act` (a page when not AJAX, `act.blade.php`), saved by `saveAct` (approaches, owner, `function`, `architecture`, `amenities`, `repair`, `completion`, `ownership_form`, `land_rights`; errors → the act page). "Alohida qulayliklar" = report `amenities` (`RealEstateReport::OPTIONS['amenities']`), not `features` (utilities, in the inspection step). Cadastral boxes: `data-cadastral` (colons and slash by themselves, by the number of digits: 14 plot, 18 building, 19 newer plot `…:FFFFF/ZZZZ`, 21 flat; `RealEstate` setter does the same); landmark: `data-landmarks-url` → `admin.landmarks` (`LandmarkController`): typed-before ones first, then the portal's own list of the district (`landmarks.kind = portal`, 18 319 names in `database/data/landmarks.json`, region → district by the Latin names of `regions.php`; added by `LandmarkSeeder` from `DatabaseSeeder` and the `2026_11_16_000200` migration; Davlatobod has none). Only a district without that list asks `LandmarkFinder` (district border by Nominatim, then Overpass `config('fairvalue.map.overpass')` servers in turn; kept in `landmarks`, `districts.landmarks_fetched_at`, refreshed after 180 days; a failure waits 10 min). The box shows the page's own list (`.landmark-list` in `admin.js`, not the browser's datalist, which could not be scrolled), narrowed by typing in Latin or Cyrillic letters, arrows/Enter/Esc; any text may still be typed. Landmark names follow the language (`Transliterator::forLocale`: Latin for `uz`, Cyrillic for `oz`, as stored for `ru`; `Transliterator::toLatin` is Cyrillic → Latin) in the list, the box, the object page and the report (`ReportScript::name`); one entry per name whichever alphabet it was typed in. A chosen one with coordinates puts the pin, others are looked for with `data-landmark-find` (Nominatim). Overpass is not reachable from the Claude cloud sessions (tests fake it).
- Analogues (`AnalogController`, `AnalogFinder`): links of `fairvalue.analogs.domains` are fetched (`PageFetcher`, only those hosts); a link of any other site (t.me, makler.uz…) is kept as a `failed` analogue for its pasted text, never fetched (`addOtherLinks`, `isWebsite`); links without https:// are understood (`AnalogController::links`). A failed one counts once price and area are typed in (a bookmark button sending listings from the browser was tried and removed at the user's request: do not bring it back). While the comparative approach is applied, `syncValue` keeps `value_comparative` in step after every change.
- Checks: `RouteCrawlTest` opens every GET route as admin/appraiser/operator, signed out and as another organisation. `db:backup` (nightly 02:40, `VACUUM INTO` storage/app/backups, newest 14; shown on the System page). GitHub Actions `.github/workflows/tests.yml`: tests + `composer audit` on every push and weekly (packagist and the advisory API are not reachable from the Claude cloud sessions).
- "So'rovnoma ma'lumotlari" (object page button, `data-act-open` like the Akt): a window `real-estates/_survey` (page `survey.blade.php`) from `RealEstateController::survey/saveSurvey`, only the customer questionnaire (`App\Reports\Survey`: questions, `answers()` decides what is stored, `usuallyNone()` for the "Mavjud emas" button, shared with step 2 of the report page). The portal's own So'rovnoma window for real estate is still unknown: match it when the user sends a screenshot.
- "Alohida qulayliklar" (report `amenities`) is one choice, as on the portal: a plain `<x-select name="amenities[]">` on the object page and in the Akt (kept as a list of one; `max:1`). `x-select` takes a `name[]` and keys its old input and errors by `name`.
- Report data fields kept in `real_estates.report` JSON (`RealEstateReport::values/defaults/OPTIONS`); option lists of the portal are in `RealEstateReport::OPTIONS`, `ValuationPurpose::portalOptions`, `Client::ORGANIZATIONS/MANAGEMENT`.
